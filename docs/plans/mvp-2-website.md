# MVP 2 - Website on GitHub Pages, built for search

**Goal:** when someone searches for a label maker, a label template or the label sheet they own, gLabels Neo
is one of the results, and the page they land on makes the download obvious.

**Status:** built and checked locally; not published. Publishing is two repository settings (below).

## What exists

| Part | Where | Notes |
|---|---|---|
| Landing page | `site/src/index.html`, `site/assets/` | Plain HTML, one CSS file, one small script, no frameworks, no external requests. Light and dark. Animated hero (a label being built, then an element snapping to the safe-area guide), live theme switcher using real screenshots, count-up numbers, a CSV-to-sheet fill demo, scroll reveals. All animation is off for visitors who ask for reduced motion, and every page works without JavaScript. |
| Template pages | generated by `site/build.py` from `templates/*.xml` | One page for each of the 1,495 label templates (for example `/templates/avery/5160/`), one per maker (32), and a searchable index. Each page has a to-scale sheet diagram, the size and layout table, the other part numbers that are the same label ("Avery 5160 = 8160, 5260, ..."), sheets from other makers with an identical layout, a how-to, a FAQ, and a **starter `.glabels` file** that opens in the app on that template. |
| Search plumbing | `site/build.py` | Unique title and description per page, canonical URLs, Open Graph and Twitter cards, JSON-LD (`SoftwareApplication`, `FAQPage`, `BreadcrumbList`), `sitemap.xml`, `robots.txt`, a 404 page. |
| Checks | `site/check.py`, `.github/workflows/site.yml` | Fails the build on a broken internal link or anchor, a missing or duplicate title, a page without exactly one `h1`, malformed starter files, or a sitemap that does not match the pages. Runs on every pull request that touches the site or the templates. |
| Pictures | `docs/assets/`, `site/assets/img/`, `scripts/make-marketing-assets.py` | Real screenshots from a test (`TestMarketingShots`) on reproducible sample projects, so they can be regenerated after any UI change. |

The 1,495 starter files were opened with the real parser (`glabels-batch-qt`) to confirm they load.

## Going live

1. **Settings > Pages > Source: GitHub Actions.**
2. **Settings > Secrets and variables > Actions > Variables: `PAGES_ENABLED` = `true`.** Until then the workflow builds and
   checks but does not deploy, so merging this changes nothing public.
3. The site is then at `https://schneiderwastaken.github.io/glabels-neo/`.

**Use a custom domain if you can.** Search engines rank a domain you own, and a bare project path
(`github.io/glabels-neo/`) shares authority with every other `github.io` site and moves if the repository is renamed.
A domain such as `glabelsneo.com` costs about the same as a coffee per month. Add it under Settings > Pages, then set
the variables `SITE_ORIGIN` = `https://yourdomain` and `SITE_BASE` = `/` and re-run the workflow. Nothing else changes,
because all links are generated from those two values.

After it is live (all free):

- Add the site to **Google Search Console** and **Bing Webmaster Tools** and submit `sitemap.xml`. This is the single
  most useful step; it also shows which searches actually find you.
- Set the GitHub repository's description, website and topics (`label-maker`, `label-printing`, `barcode`, `avery`,
  `zebra`, `zpl`, `qt`, `desktop-app`). GitHub itself ranks well, and these are free keywords.

## What to expect from search

Be realistic about the head term. "Label making tool" and "label maker" are dominated by the largest label makers,
online design tools and marketplaces with many years of links. A new site will not take that page one quickly, and a
landing page alone is unlikely to do it at all.

The achievable route is the long tail, which is where the template pages come in. People search for the part number
printed on the sheet in front of them ("Avery 5160 template", "L7160 label template", "Avery 8160 free software"),
and for "free label software for Mac", "label printing software Linux", "Zebra ZPL label designer free". These queries
have clear intent, far less competition, and the 1,495 pages cover them one by one, including the alternative part
numbers that are the same label. Plan on weeks for pages to be indexed and a few months to see steady traffic; there is
no way to promise a position.

What moves the needle, in order:

1. **Indexing and quality of the template pages** (built). Search engines discount large sets of near-identical
   generated pages. Each page here carries data that differs per template and unique cross-links, but watch Search
   Console's "Crawled, currently not indexed" count after launch; if it is high, add more unique content (below)
   rather than more pages.
2. **Links from other sites.** Submit to AlternativeTo (as an alternative to label software), Flathub, winget, Homebrew
   and Scoop when those packages exist (this also helps the download story), and post the release on Hacker News,
   Reddit (r/opensource, r/selfhosted, r/Zebra, r/smallbusiness) and Product Hunt. Real links matter more than any
   on-page tweak.
3. **Useful guides.** "How to print Avery 5160 labels from Excel", "Print labels on a Zebra printer without the driver",
   "Make barcode labels for free", "Print address labels on Linux". Each answers one search and links to the right template
   pages. Four to six good guides outweigh many thin pages.

## Risks and things to decide

- **Names and trademarks.** Avery, Dymo, Zweckform and others appear only to identify compatible stock, with a
  disclaimer in every footer, matching the README. Do not add logos or "official" wording. The comparison table
  deliberately compares against "typical online label makers" in general terms rather than named products; naming a
  competitor needs claims checked against that product's current pricing and features.
- **Template database license.** The pages are derived from the template database, which has its own permissive
  license requiring its copyright notice; it is in the footer of every page.
- **Duplicated aliases.** Part numbers that are the same label get their own page (that is what people search for). If
  Search Console shows them treated as duplicates, point the aliases at one canonical page.
- **Release links.** Download buttons use `releases/latest/download/<fixed file name>`, so they track new releases
  without a site rebuild.
- **Not yet verified:** real-device and slow-network checks, a Lighthouse run, screen-reader pass, non-Windows rendering of
  the hero artwork. The pages use no web fonts and ship about 60 KB of images above the fold, so performance should be
  good, but measure after publishing.
